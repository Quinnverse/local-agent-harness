# 清洁发行包与复验

发行脚本是交付工具，不改变宿主功能或插件协议。它在独立`.work/release/staging-*`中按允许列表复制文件，原开发数据和原始对照包不会被删除。

```sh
node scripts/package-release.mjs
```

需要Node24和本机POSIX tar；当前打包工具真实验证平台为macOS。脚本拒绝覆盖原始对照包或已经存在的输出，可用`--output`选择另一个新文件名。它生成`outputs/local-agent-harness-final.tar.gz`及相邻SHA-256文件。

## 包内容

包含完整src、两个正式插件的源码/manifest/package、测试代码和必要fixtures、依赖清单与锁文件、构建和复验脚本、README、协议/开发/安全文档、第三插件、脱敏工程基线报告和两张不含机器路径的历史结果截图。宿主及正式插件入口均由`npm run build`生成；包不依赖已有dist。

不递归复制outputs，只明确复制第三插件和安全的报告/截图。排除活动或演示注册表、安装后的用户数据、授权快照、日志、缓存、node_modules、`.work`、工具内部资料、临时文件、预构建dist、旧压缩包及含用户名路径的总览截图。

## 路径分类

A类文档/历史记录采用相对文件名或占位路径，旧机器原始日志不进入发行包。B类测试路径在各自临时目录中动态构造；不会把真实用户文件当作fixture。C类运行路径由项目位置、用户指定数据目录和当前运行输入解析；本轮未发现依赖原开发机器的硬编码，因此不改运行时源码。D类运行状态和授权信息不随包复制。

路径检查针对具体机器标识和状态数据，不会全文替换源代码中的路径逻辑或破坏正当绝对输入参数。用户在实际运行时仍可选择自己的文件目录，这是能力输入，不是随包预置授权。

## 报告与不可变包

包内`outputs/acceptance-report.md`是脱敏工程基线和证据范围说明，历史截图明确标记为历史。最终新包的安装、测试、浏览器、真实进程重启、故障和第三插件验证必须在打包后全新解压执行；结果写入包旁的`release-gate-report.md`，绑定最终SHA-256。不会在验证后再向压缩包塞入结果而偷偷改变其哈希。

打包成功仅表示文件被打包，脚本状态为PACKAGED_NOT_YET_RUNTIME_ATTESTED，不代表运行验收成功。工程门槛和独立正式提交说明合规性分别报告。正式说明缺失时必须是SUBMISSION_COMPLIANCE=UNKNOWN，不将其混成一个PASS。
