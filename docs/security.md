# 安全边界与已知限制

## 信任模型

只安装你信任的本地插件。每次执行使用独立Node子进程，但它仍以当前操作系统用户身份运行。普通子进程不是完整安全沙箱；manifest的权限不是Node或操作系统强制访问控制。恶意插件可以直接访问文件、网络、子进程和其他系统资源，可能修改宿主注册表或其他插件。不能用本项目安全运行任意不可信第三方代码。

## 实际实施的保护

宿主文件broker要求插件声明files.read并由用户单独授权目录。安装默认禁用、无授权。broker解析文件真实路径，按目录边界检查范围，不接受越界链接、特殊文件、无效UTF-8或超过1MiB的内容，使用O_NOFOLLOW避免最终路径组件被替换为链接。普通路径检查仍不能消除对手可并发替换父目录等所有TOCTOU竞态，授权目录应是可信、本地、稳定的目录。

插件异常、加载失败、进程退出和执行超时转换为结构化错误。超时SIGKILL，并在执行进程exit后返回；不把“发送了信号”当成已终止。结果返回后进程也回收。设置Node堆大小参考上限，但不是操作系统内存/CPU配额。日志64KiB、结果1MiB、broker请求128次上限不能阻止恶意代码所有资源耗尽行为或巨量IPC反序列化分配。只保证直接执行进程回收，不保证清理恶意插件启动的全部后代。

子进程不继承完整宿主环境、CLI参数或模型密钥，只有固定语言环境及Node管理IPC所需变量。错误默认不返回原始堆栈、插件异常文本和完整敏感配置。可信本地管理用户可以看到安装位置和授权路径。日志不持久保存，执行历史不持久化。

## 本地Web

仅监听127.0.0.1，不支持公网监听。校验Host，Origin出现时要求同源；写请求需要启动时随机token、JSON Content-Type，限制请求体。不开放CORS。静态资源允许列表、CSP和textContent输出避免路径遍历及插件描述注入。浏览器跨站请求受到防护，但本机同用户程序可以读取session并调用API；这不是多用户身份认证。

管理Web有安装和执行可信代码的能力。不要将端口通过代理、隧道或端口转发公开。未来若接入公网或多用户，必须另行设计身份认证、授权、隔离和审计。

## 状态与失败恢复

注册表版本为1，用跨进程锁串行修改；配置先验证副本再原子替换，并同步临时文件。安装采用staging和注册表提交点；失败不注册未完成包，下一次安装在写锁内清理残留staging和未引用包。不是跨文件系统的完整数据库事务，也不保证突然断电后的所有目录元数据已持久化。不要手工编辑运行中的注册表。

注册表损坏会报STATE_CORRUPT，不会自动覆盖。写锁遇到存活进程则等待后报STATE_BUSY；异常遗留无法确认所有权的锁应由用户确认宿主均已退出后处理。插件包没有签名或运行前哈希验证，同用户能篡改已安装入口；仍属于可信代码边界。

## 首版不提供

操作系统沙箱、插件签名/市场、自动更新/卸载、热加载、常驻插件、完整模型编排、多用户认证、执行历史、网络/子进程强制权限。SDK保留AgentAdapter契约，没有接入LLM，也没有固定规则伪装推理。跨平台源码可移植，但当前真实验收仅在macOS与Node24完成；其他平台需另行验证。
